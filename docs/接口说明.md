# CrateLoop 接口与数据规则

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 微信 zhuatech / zhuatech2。公开源码学习版，商业使用须取得书面授权。

同源 `/api`，JSON 请求；会话 Cookie HttpOnly/SameSite Strict。先 GET `/auth/csrf` 获取 header/token，再 POST `/auth/login`；所有写入包含对应 CSRF 请求头。GET `/auth/me` 返回安全账号、菜单、权限和数据范围；POST `/auth/logout` 使会话失效；POST `/auth/password` 输入 oldPassword/newPassword，成功后退出。健康路径 `/actuator/health` 公开，仅返回健康状态。

| 路径 | 方法与权限 |
| --- | --- |
| `/options` | GET：可见池基本信息、伙伴、器具字典、时区与显示名；绑定伙伴不读全池量 |
| `/pools` | GET pool.read；POST catalog.write、内部岗位 |
| `/partners` | GET/POST catalog.write、内部岗位 |
| `/pools/{id}` | GET pool.read；PUT/DELETE catalog.write、内部岗位 |
| `/partners/{id}` | PUT/DELETE catalog.write、内部岗位 |
| `/movements` / `/movements/{id}` | GET movement.read；POST/PUT movement.write；仅草稿可改 |
| `/adjustments` / `/adjustments/{id}` | GET adjustment.read；POST/PUT adjustment.write、内部岗位 |
| `/statements` / `/statements/{id}` | GET statement.read；POST statement.write、内部岗位，冻结当前余额 |
| `/{type}/{id}/commands/{action}` | POST；type 为 movements、adjustments、statements，权限和状态见下表 |
| `/{type}/{id}/report.json` | GET export 加对应详情权限及范围；type 为 pools、movements、adjustments、statements，无宣传载荷，no-store |
| `/dashboard` | GET dashboard，仅当前可见数量和单据 |
| `/audit` | GET audit、内部岗位，SELF只读本人，最多500条最近操作 |
| `/admin/{type}` / `/admin/{type}/{id}` | GET/POST/PUT/DELETE admin、内部、ALL范围；type 为 users、roles、departments、permissions、menus、dictionaries、settings |

主数据输入 requestKey、version（编辑必填）、reference、name、departmentId、enabled，池另含 kind（器具字典码）。不接收客户端直接覆盖资产桶。交接输入 requestKey、version、reference、kind（ISSUE/RETURN）、poolId、partnerId、quantity。提案 kind 为 ADD/REPAIR/RETIRE，维修另填 goodQuantity/retireQuantity 且之和等于 quantity。对账输入 requestKey、reference、poolId、partnerId。

列表 query 参数：search（最多200字符）、status、kind、page（0起）、size（1～100）、sort（newest/reference）。返回 items、total、page、size。主数据 status 使用 true/false。业务详情 record、基本pool、partner及balance（涉及伙伴时）、events、ledger；池详情为 pool、balances、ledger。对账 record.snapshot 是冻结的 JSON 字符串；页面解析为数量和流水，不开放任意快照写入。

| 对象动作 | 前置状态／权限／数量字段 |
| --- | --- |
| movements submit/cancel | movement.write；提交DRAFT，取消DRAFT/SUBMITTED/RESERVED；已批准借出取消限内部 |
| movements approve/reject | ISSUE SUBMITTED、issue.approve、内部且不同制单人 |
| movements dispatch | RESERVED、dispatch、内部 |
| movements receive | DISPATCHED、receive、不同于发运人；quantity 为实际接收量，0～申请量；RETURN限内部 |
| movements resolve | DISPUTED、shortage.review、内部且不同于制单/发运/接收；ISSUE recoveredQuantity+lostQuantity=短缺，RETURN backToPartner+lostQuantity=短缺 |
| movements inspect | RETURN QC_PENDING、quality.review、内部且不同接收人；goodQuantity+repairQuantity+retireQuantity=实收 |
| adjustments submit/cancel | adjustment.write、内部；提交DRAFT，取消DRAFT/SUBMITTED |
| adjustments approve/reject | SUBMITTED、adjustment.approve、内部且不同制单人 |
| statements confirm/dispute | OPEN、statement.confirm、不同制单人；确认还检查无待完成交接及截止流水未变 |
| statements cancel | OPEN/DISPUTED、statement.write、内部 |

每个命令 body 必须有 requestKey（UUID）、version（当前记录版本）、note（1～1000字符证据）；另附动作相关数量。申请／提案数量1～100万；分类量0～100万，JSON 小数不会被静默取整。池总量上限1亿。后台响应时间使用UTC，页面按 Asia/Shanghai 展示。

相同 UUID 必须完全相同账号、对象、动作和载荷，返回当前记录不重复过账；改载荷重用 UUID 返回409 REQUEST_KEY_REUSED。失败事务不占用UUID。已成功保存后若回包丢失，应以同载荷重试，再刷新当前记录；页面在未变更载荷时保留重试键。

错误响应只含 code：401 UNAUTHENTICATED/LOGIN_FAILED，403 FORBIDDEN/OUT_OF_SCOPE/STAFF_ONLY，409 STALE_VERSION/INVALID_STATE/INSUFFICIENT_QUANTITY/INDEPENDENT_REVIEW_REQUIRED/STALE_STATEMENT/PENDING_HANDOFF/OPEN_STATEMENT/BALANCE_INVARIANT/CONFLICT，400 INVALID_INPUT/INVALID_QUANTITY/INVALID_REQUEST_KEY/QUANTITY_MISMATCH，429 LOGIN_THROTTLED。并发写由共享事务锁序列化，失败回滚全部数量、证据和命令凭据。

没有流水更新／删除接口，没有租金、支付或文件上传接口。数量差错按受控业务流程处理；不通过修改接口返回值或历史快照掩盖差异。
