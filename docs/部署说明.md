# CrateLoop 部署、升级与恢复

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 商业咨询微信 zhuatech / zhuatech2。

## 本地完整启动

Docker Desktop／Engine、Compose v2、Python3.10+。根目录运行：

```sh
python3 scripts/init-env.py
docker compose -p crateloop config --quiet
docker compose -p crateloop up -d --build --wait
```

配置已存在时生成器拒绝覆盖。`.env` 保持0600、被Git和镜像忽略；root数据库、应用数据库及初始化管理员分别使用独立随机值。默认浏览器8127，覆盖端口可用 `WEB_PORT=18127 docker compose -p crateloop up -d`。数据库不向外发布，使用自己的Compose项目名隔离容器与卷。

## 开发进程

前端 Node24.19.0/npm11，`cd frontend && npm ci && npm run dev`，Vite默认5173、代理本地后端8080。后端 Java21/Maven3.9，设置 DATABASE_URL、DATABASE_USER、DATABASE_PASSWORD、ADMIN_PASSWORD，运行 `mvn -f backend/pom.xml spring-boot:run`。JDBC使用 `jdbc:mariadb://` 访问MySQL，DATABASE_CATALOG默认zhuatech_crateloop，切换库时同时覆盖目录名。

需要宿主机进程连接容器MySQL时，在私有临时Compose覆盖文件给mysql设置 `ports: ['127.0.0.1:13307:3306']`，运行 `docker compose -p crateloop -f compose.yaml -f <自己的覆盖文件> up -d mysql`，JDBC端口13307。覆盖文件不含真实客户数据，也不提交生产配置。开发数据库仍沿用本项目独立卷。

## 备份

仅保存到受控、忽略且权限受限的私有目录：

```sh
umask 077
mkdir -p private-backups
docker compose -p crateloop exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump -ucrateloop --single-transaction --no-tablespaces zhuatech_crateloop' > private-backups/crateloop.sql
```

备份包含账号散列和业务数据，禁止上传到公开仓库。记录时间、版本和校验值。备份时仍需考虑管理员目录变更和业务写事务；恢复验收用停写快照。

## 独立恢复验收

新建独立项目，前端使用18127。先起空MySQL，再导入备份，然后启动应用。不要在未知或生产卷上覆盖测试数据。

```sh
WEB_PORT=18127 docker compose -p crateloop-restore up -d mysql --wait
WEB_PORT=18127 docker compose -p crateloop-restore exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -ucrateloop zhuatech_crateloop' < private-backups/crateloop.sql
WEB_PORT=18127 docker compose -p crateloop-restore up -d --wait
TEST_URL=http://127.0.0.1:18127 python3 scripts/smoke.py --verify
```

恢复项目须使用相同已验收镜像或完整重新构建镜像；若使用自定义Compose项目名导致未有镜像，追加 `--build` 或在私有覆盖文件指定已验收镜像。验收脚本依赖同一份私有 output/qa-state.json；实际生产恢复另按自身数据和账号做确认。完成后只清理自己创建的恢复环境：`docker compose -p crateloop-restore down --volumes`。

## 版本升级与生产

升级前停止写入，备份并验证恢复。记录当前Flyway版本，更新代码及镜像，启动后端等待迁移与健康，再开放前端。V1身份目录、V2器具领域；校验失败先核查日志和可信发布文件，不能删迁移记录、改已执行脚本或删卷“修好”。已有密码不由ADMIN_PASSWORD反复重置。

生产通过可信Nginx／网关使用HTTPS，COOKIE_SECURE=true，默认仅本地绑定；公网开放、证书、域名和外部数据库映射需按自身部署配置。MySQL8.4持久卷和强密码不等于自动备份或高可用。配合 SECURITY.md 的最小权限、网络隔离、备份与恢复管理。

健康失败时查看 `docker compose -p crateloop logs --tail=100 mysql backend frontend`，核对端口、凭证名称、数据库目录与迁移；日志脱敏后再分享。只停止本项目，不能影响其他Compose环境。
